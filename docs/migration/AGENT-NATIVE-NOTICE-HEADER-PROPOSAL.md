## Proposed bounded representation

After root explicitly reviews a future implementation, a policy3 may add **exactly these24** `sourceHeaderCandidates` records alongside the closed two-AUTHORS records. Unknown package/version/source/checksum/path/size/hash/offset/kind, missing/duplicate/extra records and additional keys must refuse. No source-file glob, keyword scanner, generic SPDX text retrieval or unversioned upstream substitution is proposed. Verify complete archive checksum and complete source bytes first, then the bounded raw range; matching a familiar prefix in a changed source file is insufficient.

Keep existing whole-file `texts` semantics and counters unchanged. Current validation compares each text blob with the entire authoritative file: storing a fragment there would weaken that invariant. Prefer a new receipt2 package `perFileNotices` array with explicit source/range descriptors and a separate inventory section/origin count. Preserve receipt1 and policy1/2 behavior for historical47, recovered-three57/current58 and AUTHORS70/future71 controls. Older readers must clearly refuse the new schema; source/project guards intentionally make old current resources stale after adoption.

Each partial-notice origin should retain its evidence kind and exact range/full-source identities. Empty arrays for unselected packages must not assert absence of licensing elsewhere. Existing filename-discovery availability/gap counts should remain based on whole-file selections: finding a header does not supply its referenced full text. Report24 header origins/four distinct range blobs separately; final combined blob dedup against other resources must be measured. Do not count partial notices as newly recovered whole-file license texts or infer target linkage from the lockfile, especially the GNU winapi support packages in an MSVC corpus.

## Meaningful future guards

- Reparse immutable private archives and verify every closed record, full source hash and range bytes; never promote ambient cache additions. Missing source remains unknown/nonblocking; a present malformed source/range refuses before publication.
- Refuse changed source bodies with identical headers, shifted offsets, off-by-one/truncated ranges, normalized newline/comment bytes, alternate paths/case/versions/checksums, duplicate origins or unknown records. Repeated range bytes may deduplicate while preserving all24 distinct origins.
- Recompute every public receipt/output/stamp hash after changing header bytes, full-source descriptors, classification or availability; independent private archive/policy binding must still refuse. Do not silently downgrade/move to an older admission or weaken whole-file equality to make a fragment pass.
- Preserve old whole-file/gap/count/cold-cache/coherent-tamper/current-pointer/target/rollback and build/dev/bundle-order gates through explicit historical fixtures, not loose counter ranges. Add a new owned partial-notice mode and future current-root acceptance only after intentional generation; preserve earlier native/resource proofs as historical.
