## DNS failure backoff scheduling (2026-10-19)

The shared per-resolver lookup cache now owns default backoff timing: 1000ms initial, 1.6 multiplier, 120000ms cap before +/-20 percent jitter, fractional milliseconds truncated. The clock begins at attempt start so a slow failure spends its own delay; success clears/reset backoff. A later independent connector/worker request waits only the remaining failure backoff. Overlapping callbacks still share the same completed answer/error. DNS failure replaces the successful 30-second minimum deadline with the failed attempt backoff deadline and retains previously published LB addresses. No unconditional failure polling/retry loop is introduced: another LB/connector request is required.

Resolution timing has its own watch signal, separate from policy/address revisions. The RR worker re-evaluates a deferred deadline when another lookup changes timing, including clearing the minimum timer on error; this does not cancel a pending policy build. Failure publication checks both target generation and exact latest attempt start. Target retirement remains handled by the existing owned-worker cancellation.
