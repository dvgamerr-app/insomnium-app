# OAuth1 signing boundary

OAuth1 editor and environment preparation produce a structured native configuration; JavaScript does not calculate request signatures. The existing signed-request executor (digest.rs) buffers once and signs OAuth1 against each effective request before sending. Redirects only attach signatures at the original origin. Native OAuth1 uses RustCrypto HMAC/SHA/RSA; RFC percent-encoded parameter sorting is explicit and independent of cryptographic primitives. The alternative oauth1-request 0.6.1 was inspected but its raw-key ParameterList sorting and fixed builder options do not cover dynamic encoded-key ordering plus original body/version behavior. No dependency on that alternative was added.

Existing Insomnium records default to visible legacy body behavior; new records and Postman use RFC form signing. No silent fallback across algorithms, body modes or parameter destinations. See AUTHENTICATION.md#record-oauth1-compatibility for exact limits and inspection evidence. No new IPC command/capability is needed; OAuth1 remains within the three existing HTTP/stream command paths. OAuth2 token endpoint builders explicitly clear OAuth1 and Digest configuration.

## Native and browser storage

Desktop: Tauri app data directory for `app.insomnium.desktop` contains `workspace-v1.json`. First save over an existing file each session copies the previous content into `workspace-v1.previous.json`. Invalid files fail loading and block saving; they are never silently reset. Single-instance plugin prevents concurrent desktop writers. Closing flushes the latest state before destroying the window.

Native cookies: `cookies/<collection-id>.json` is separate from workspace resources, with `.previous.json` created before the first write each session. Cookie edits commit atomically before updating memory; response cookies flush after request completion/cancellation. Collection duplication does not copy the native jar. Cookie files and workspace files must both be included in a full backup.

Browser preview: separate `localStorage` key `insomnium-tauri-preview-v1`. Browser storage limits/CORS apply; this is not the desktop backend and is not the migration source.

Data format uses Insomnia-style `_id`, `_type`, `parentId` resources inside a `schemaVersion: 1` document. Settings and bounded history are separate root fields. Credentials currently remain in local plain JSON as in legacy export; OS credential vault migration is outstanding.

## Compatibility boundaries

No Electron/React runtime or legacy Node dependencies are executed. No server/Node sidecar is bundled. JavaScript tooling uses Bun; frontend runs inside the OS WebView; native backend is Rust.

Unknown auth and legacy template tags stop the request with a clear error. Postman scripts are preserved and block affected requests pending script migration. gRPC resources use the dedicated GrpcPane, saved proto/reflection schema, native Tonic HTTP/2 transport and acknowledged Channels. Legacy JSON is the default; explicit ProtoJSON is separate. Schema/call contexts participate in cancellation and shutdown. Native responses have a current 20 MiB limit. Cookie jars are persisted by the native backend, including session cookies; HTTP auth/cookies/proxy do not apply to gRPC. Limits and remaining compatibility are tracked in PARITY.md and GRPC.md#record-grpc-compatibility.

WebSocket/SSE run only in the native backend. Saved WebSocket payload IDs are remapped when importing/duplicating. SSE uses a single connection per Connect action and exposes server retry metadata without automatic replay. Established streams are not limited by the HTTP total timeout. Recent logs retain up to 1,000 events / 8 MiB, keeping one oversized newest event intact; the overall serialized history budget remains 40 MiB. Closing the window cancels active operations, waits for their final state and flushes persistence. Legacy external stream log files are not imported.

Client certificates are selected for an exact hostname in the frontend and restricted to the original scheme/host/port during redirects in Rust. Per-request legacy redirect settings are respected. Separate send/store-cookie switches are implemented through per-request cookie providers. API-key cookie destinations remain explicitly rejected.

## API Design boundary

API Design is a sibling view to request debugging, using the same Insomnium activity rail, collection selection and theme. api_spec resources keep original contents, contentType, fileName and attached files. Source edits persist through the existing serialized atomic workspace storage. Import is additive. Validation does not mutate source or send requests.

The view starts a module Web Worker only on Validate/Generate. YAML parsing, static structural schema checks, attached-file dereferencing and sample generation run there. The worker is terminated on cancel/unmount/15-second deadline. A source snapshot prevents stale results from generating resources after an edit. Validators are generated with Ajv standalone during Bun prepare and bundled separately from the main UI; CSP remains script-src self with no eval.

Generation selects operation/path/root server precedence (or explicit override), maps scalar parameters, supported bodies and Basic/Bearer/API key placeholders, and adds a new folder without modifying existing requests. sourceSpecId/sourceOperation retain provenance and sourceSpecId participates in import/subtree ID remapping. Complex mappings produce _openapiIssues; transport blocks sending until the owner corrects fields and explicitly acknowledges them in Settings. This acknowledgement never removes _migrationIssues from other importers. Full Spectral rules, advanced serialization and 3.2 additional operations remain separate parity tasks.

## Digest authentication boundary

The request editor stores the existing authentication type/username/password/disabled fields. JavaScript renders environment variables, removes a competing Authorization header and passes resolved credentials only to native transport. Browser preview rejects Digest before fetch. The generic enabled control also restores access to the legacy disabled flag.

src-tauri/src/digest.rs wraps both reqwest::Response and WebSocket UpgradeResponse. HTTP, SSE and WS use the same challenge executor, existing TLS/proxy/cookie client, cancellation and timeout. It buffers the exact built body once (20 MiB), so multipart retry/signing uses the original boundary and bytes. The parser handles challenge lists; digest_auth calculates hashes. Each operation starts without cached/preemptive Digest; at most one ordinary challenge response and one stale retry per hop.

Automatic reqwest redirects are disabled for active native Digest/OAuth1/AWS signing. Manual Authorization bypasses Digest/OAuth1 signing; AWS explicitly replaces it. The executor applies up to ten redirects, reproduces POST-to-GET and 303 behavior, clears Authorization on each hop and only computes Digest for the original origin. Cross-origin redirects clear manual Cookie/Proxy-Authorization; the cookie provider still applies normal domain/path scope. Client certificates remain bound to the original origin. HTTP timeout now wraps the whole operation including retries/body read; streaming timeout still ends after handshake. No challenge state is saved to workspace/history. Response Authentication-Info/rspauth verification and proxy 407 authentication remain separate parity work.

## Digest Unicode compatibility patch

The earlier non-ASCII challenge limitation is resolved with a local Cargo override of http-auth 0.1.10. See src-tauri/vendor/http-auth/PATCH.md and UPSTREAM.json for the minimal diff, licenses and original hashes. Its original state machine still validates challenge lists; only RFC obs-text within quoted fields/quoted-pairs is admitted. Non-ASCII scheme, parameter names and unquoted token values remain rejected. Invalid UTF8 header bytes are rejected before parsing.

Parsed fields are mapped to digest_auth::WwwAuthenticateHeader directly. Its separate text parser is not used, because it mixes character and byte offsets. Realm/nonce/opaque preserve the server bytes after unescaping. Username and password are NFC-normalized only for explicit charset=UTF-8, matched case-insensitively; stored credentials remain unchanged. Unhashed non-ASCII usernames use username*=UTF-8'' percent-encoding. userhash continues to hash normalized username and exact realm. Existing challenge retries, origin isolation and body replay are unchanged.

## OAuth token lifecycle

OAuth preserves legacy request.authentication fields and oauth2_token child resources. oauth-model.js resolves variables and computes a SHA-256 fingerprint (noble-hashes) without persisting the resolved credentials. oauth.js builds a separate token request against the token URL, selecting the client certificate for that endpoint rather than the API host. Native http::fetch_oauth_token owns cookie/cancellation/deadline handling; oauth.rs uses oauth2 5 builders and a bounded reqwest AsyncHttpClient adapter. Basic credentials use RFC6749 form encoding; body credentials, scopes, audience/resource and Origin are supported. Redirects are always disabled for token exchanges. Standard Bearer JSON token responses are required; ID tokens are kept separate.

The shared workspace completion map covers explicit Fetch/Refresh and automatic exchange before HTTP, GraphQL introspection and WS/SSE handshakes. A live context check rejects stale responses after auth/environment/recipient/network changes. Abort checks stop a subsequent resource send. A failed refresh leaves the earlier record and stops the resource request; no automatic password/client retry follows invalid_grant. Native token responses never replace response/history. Once a stream is open, expiry does not trigger reconnect.

Tokens use the existing atomic workspace store, remain plaintext and are exported with resources. One active native token is replaced per request; imported records are marked _oauthImported and never silently rebound or removed by Fetch/Clear. Explicit adoption creates a native copy with the current fingerprint while retaining the source. Copies of request/folder/collection trees exclude token resources, matching legacy canDuplicate=false. Missing refresh rotation retains the prior refresh token only for refresh exchanges; a new grant starts a new token family.

Auth UI retains the original Insomnium tab/layout/styles. New OAuth selection starts at Client Credentials; an existing unsupported grant remains visible with its data intact. Password is labelled legacy. Authorization Code/PKCE and Implicit share the implemented browser/callback lifecycle described below. Postman manual accessToken/headerPrefix is understood; query destinations, empty prefixes and non-Bearer types stop visibly until explicitly corrected. Manual access tokens bypass fetching and have no tracked expiry.

## Authorization Code and PKCE

Native OAuthConfig now carries authorization URL, redirect URL, state, PKCE method/enable flag, callback mode, response type and optional expected issuer. oauth_callback.rs builds the authorization URL with oauth2 5 and owns the verifier until token exchange. State is random by default (library 128-bit value) or the configured legacy state; comparisons use the timing-resistant library feature. PKCE defaults to S256; explicit plain/disabled remain supported. Reserved OAuth query parameters in the authorization URL are rejected rather than duplicated. Extra provider query parameters remain intact.

prepare_redirect binds only an HTTP loopback address, preserving an explicit fixed URL/path/query. Blank redirect uses an available loopback port. Non-loopback/HTTPS/custom schemes and explicit manual mode never bind a server and instead accept the final URL through the Auth UI. Manual callbacks and network callbacks use the same exact scheme/host/port/path/static-query, unique-parameter, state and optional issuer checks. No raw provider description or callback URL enters errors. Invalid callbacks keep listening; a valid denial ends the attempt without token exchange.

The Hyper HTTP/1 loopback server uses the documented service_fn/TokioIo pattern with explicit 5-second header-read/10-second connection deadlines, 16 KiB buffers, 32 headers and up to 16 owned tasks. Code callbacks require one matching Host and GET, reply with a fixed no-store/plain-text acknowledgement, and abort owned connections when the future ends. Implicit additionally serves the narrowly scoped fragment relay described below; no general web server or wildcard bind.

oauth_browser.rs registers transient per-run callback state and sends waiting/exchanging progress over a Tauri Channel. The installed opener plugin opens the system browser. The five-minute login wait is independent of the normal token HTTP timeout; shared NetworkState cancellation and workspace completions include the entire operation. A Drop guard removes callback state on every exit. The code/verifier stay native; only a manually pasted URL crosses IPC transiently. Progress and manual text do not enter workspace/history. System-browser login sessions are distinct from the app cookie jar; token exchange still uses the existing TLS/proxy/cookie settings.

## Implicit fragment callbacks

AuthorizationRequest::set_response_type selects token, id_token, id_token token or none. Default response modes are retained: fragments for token variants and query for none. Implicit omits PKCE and token HTTP exchange. A fresh library nonce is added for ID-token variants. oauth_implicit.rs parses bounded callback fields, Bearer tokens and checked expiry; compact ID-token syntax and transaction nonce are checked, but signatures/identity claims are not verified. This API client does not establish an authenticated OpenID user. ID tokens remain metadata unless the explicit useIdentityToken option selects one as the API credential; credentialKind persists this choice. Sending a known saved ID credential requires that option too.

CallbackResponse separates Code, Tokens and Empty. Code uses the existing bounded token adapter; Tokens return directly; Empty returns null to Svelte, where explicit authorization reports completion and automatic resource sending stops without a token. Refresh continues through the token endpoint. Existing stale-context, cancellation, registration-drop and completion-draining behavior covers all variants.

URL fragments never reach HTTP servers. An exact loopback GET therefore returns a small native-owned HTML page with a fresh script nonce/CSP and per-attempt relay secret. oauth-fragment.js captures the callback, clears its fragment with history.replaceState, and POSTs the original URL back to the same path/static query. Native code requires exact Origin and secret, caps the body at 16 KiB with http_body_util::Limited, then calls the same validator as manual paste. No cross-origin preflight is supported. A failed POST exposes the original URL only in a transient readonly textarea for manual recovery. All responses are no-store/no-referrer/nosniff; application WebView CSP is unchanged. This local relay POST is not provider form_post support.

Known boundaries: actual browser/CSP/provider/Tauri acceptance is pending; system-browser remote/custom-scheme callbacks require paste; no encrypted ID tokens or JWT identity verification. Implicit expiry uses expires_in and does not infer JWT exp. Native core, exact relay JS and compiled Svelte/mock-IPC inspections provide narrower evidence recorded in STATUS/ACCEPTANCE.
