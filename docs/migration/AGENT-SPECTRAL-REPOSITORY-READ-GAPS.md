## What is actually owned

`src-tauri/src/spectral.rs::binding` validates whole expected Git resource equality, unique registered nonprivate collection/repository/spec ancestry, pending-transition/intents and canonical managed path under Git→Storage locks. Those guards drop when binding returns, before serialization/spawn. RUN snapshots immutable opaque sourceJson; it does not hold a repository generation lease. After physical execute and parse_reply, it immediately calls `spectral_jobs.rs::settle`, which linearizes cancellation/owner/deadline with success publication. There is no second registered binding check, repository epoch or consumed-input check. GitState is a Mutex, not a monotonic generation counter. Git locks around app operations are not held during the sidecar operation and do not cover external editors.

`tools/spectral-linter/host.js` builds a per-job known URI map from captured main/attached input, then actual external reference retrieval. Attached URI wins; repository retrieval canonicalizes and checks containment before streaming bounded UTF8 bytes, remote retrieval streams bounded fetch bytes. Successfully retrieved reference contents are returned, with actual origin/URI. This is a useful consumed-reference snapshot; it is not a native freshness receipt. Custom rules are loaded separately through public bundleAndLoadRuleset({fs,fetch},[builtins()]). Ruleset YAML/extends/custom function/import bytes and failed reads that trigger fallback are absent from the returned source catalog. Installed package imports delegated externally are not proven by recording the entry YAML. The protocol outer result frame currently has only protocol/jobId/opaque resultJson; Rust deliberately does not decode diagnostic strings containing lone surrogates.

`spectral-sources.js::createSpectralSourceCatalog` checks exact identity/shape/duplicates, input equality for main/attached, external raw catalog limits and diagnostic mapping. It cannot compare a repository file with its current disk contents. `spectral-client.js` detaches inputs and owns UUID/cancel/process settlement. `ApiDesign.svelte` rejects changed input, workspace object/collection and binding resource key; it joins structural analysis/Generate to the same accepted captured catalog. These guards do not observe changes solely to other/.spectral.yaml, custom JS or repository refs. Each Generate does start a fresh job, which prevents reuse of the previous validation snapshot but does not prevent changes during that fresh job.

## Exact uncovered interleavings

1. Existing registered held fixture loads rule/function A; its actual pause marker proves entry. While the original four-second function is pending, write B to the owned other/.spectral.yaml, keeping registered resource/main/attached/workspace unchanged. Allow A to finish without cancel. Current RUN/client/parent guards accept A although the rule file is now B. A future saved negative can reuse the registered UUID/canonical profile/allowlisted writer and retained physical process object; it must not bypass ownership or weaken the existing configureCase no-live-observer rule.
2. During the same hold, alter an already captured repository reference A→B. Catalog/structural worker correctly use captured A, but nothing marks that result stale relative to disk B. Independently changing a file before it is first retrieved can produce a mixed-time catalog across nested files. A held custom function can make its final result depend on a later declared file read; that needs an actual receipt at consumption time, not only an initial path/HEAD check.
3. ABA: A→B→A before publication defeats a final-only hash compared with an initial snapshot. If the producer consumed B, a producer-consumed-byte receipt rechecked against current A detects mismatch. If it consumed A before and after transient B, hashes establish content coherence but not the stronger no-change-during-job guarantee; that requires an authoritative monotonic owned mutation epoch. External filesystem writers need a separately proven observation/atomicity contract; a watcher or matching HEAD must not be presented as universal ABA proof.
4. Missing/invalid ruleset or extend selects fallback; create/fix it while default lint is pending. No missing/failure receipt is rechecked, so fallback can be published after custom rules become usable. Renames/symlink or managed binding changes after initial lock validation are also not revalidated by Rust. Frontend object guards cover visible app changes only, not an independent saved-resource transition invisible to that in-memory object.

These are concrete code interleavings, not reproduced failures in this report. Unknown trusted custom JS may read arbitrary files/network/environment, spawn children or perform effects; legacy compatibility permits that authority. Recording declared YAML/import/ref dependencies must not silently impose a sandbox or claim ambient effects deterministic.

## Bounded next design, not authorization to implement

First reproduce case1 in an explicitly owned saved fixture writer with exact A/B bytes, marker/UUID/process identity and full restoration; preserve its negative. Then define separate outer receipt metadata so resultJson stays opaque. Public fs/fetch supplied to the bundler and resolver can record declared consumed raw bytes and missing/fallback outcomes; native must canonicalize managed-relative paths, validate limits/identity and recheck before publication under the documented lock order. A monotonic lease for app-owned Git mutations is a different contract from content hashes and must cover the exact mutation entry points. Arbitrary trusted ambient effects, remote freshness and unobserved external ABA remain explicit limits rather than new authority or a whole-tree hash shortcut.

Public [Rollup load hooks](https://rollupjs.org/plugin-development/#load) can observe a module loader's supplied bytes; [Bun runtime plugins](https://bun.sh/docs/runtime/plugins) expose onResolve/onLoad import hooks. Neither API is proof that every fs read or trusted ambient effect is intercepted. Current pinned builtins plugin has a public options hook controlling external delegation; package closure coverage needs behavior equality for primitive exports/JSON/cycles/dynamic require/__dirname/native/builtin modules before adoption. Do not add private require patches, plaintext spec staging, new fetch scope or forced package bundling from partial coverage.

All original consumed-read/generation/inflight/private/platform/distribution/unobserved-process/hardFS/restart/SDK/Event/FIFO/migration/UX gates remain. No live handles/profile claim. Report-only topic and STATUS handoff required; /compact is unavailable here.
