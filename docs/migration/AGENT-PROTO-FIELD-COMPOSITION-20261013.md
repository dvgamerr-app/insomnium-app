## Exact proposed model contract for root review

Current `src/lib/grpc-model.js:110` validates count first, then each file in order: filename/path/suffix/duplicate condition, per-file/aggregate UTF8 limit, then file/directory collisions after the loop. Preserve that complete ordering and every actual message. A later duplicate must never be field-classified before an earlier size/count refusal. Do not perform a parallel heuristic filename scan in ProtoManager or parse arbitrary caught strings.

Propose narrowly branding only the actual existing filename Error at its current throw site with private module-owned WeakMap metadata. Export `protoFilenameIssue(error)` returning null for any unregistered error, otherwise a frozen issue `{kind:'invalid-name'|'duplicate-name', name:string, rows:readonly number[]}`. The same actual Error instance and message propagate through the unchanged import/replacement path. The lookup accepts unknown values safely; backend/transport/admission errors cannot acquire ownership by matching a property or text.

At the existing combined condition, retain the same invalid-name predicate and seen-name check, then create the exact existing Error. The loop can use `files.entries()` for its actual zero-based index. For invalid name/suffix, metadata rows contains only that index. For duplicate name, rows contains the earlier matching index and current index, determined only after the authoritative duplicate branch is reached. Keep existing seen Set, UTF8 computation, totals and subsequent collision loop unchanged. Store the immutable record in the private WeakMap before throwing. Count/size/collision branches remain plain unbranded errors; no quota changes or exception-message changes.

This model change is proposed only; neither the copied model nor production model was edited. An owner-approved implementation must verify count precedence, earlier size refusal before later duplicate, invalid-before-size ordering, UTF8 bounds, duplicate indices, collision remaining global, and arbitrary Error/string lookalikes returning null through the actual validator. No generic backend/API exception type is introduced.

## Proposed parent ownership and correction boundary

Only accept the lookup result for the current captured pending batch/request/data/epoch and matching row values, after the actual apply validation refuses. Store a separate filename owner record; do not overwrite unrelated form feedback. Feed its exact current message to the row's existing Field.error. Duplicate rows require distinct IDs/error-description IDs and aria-invalid on both, with exact indexed names unchanged.

On edit, rerun the same complete pure validator rather than duplicating its predicates. Retain/update an existing owner only if the resulting branded failure still identifies that owner; retire it when its accepted refusal no longer describes the current batch. Do not publish a new unrelated row error or turn a new size/topology/backend refusal into Field feedback merely because the user edited a name. In particular, the measured unrelated valid second-row edit must keep the still-invalid first-row refusal, while resolving the actual duplicate pair must retire both descriptions. Corrections alone never save. Root must review exact behavior when a different earlier failure now takes precedence.

Keep generic current File.text failure, workspace/admission/persistence, browser native-unavailable/schema/backend refusal and saved-name rollback-to-valid global/unmarked. Selection/discard/success/destruction must retire the local owner without weakening existing keyed-lifetime or focus guards. Inline duplicate alerts may require a presence-only wait plus exact duplicate count/IDs/descriptions in the saved scenario; do not replace the actual refusal/no-save assertions with a broad count check. Error geometry and all138 original focus/lifecycle/data assertions must be reverified on any product candidate.
