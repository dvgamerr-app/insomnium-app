## Current implementation stage

`grpc_service_config.rs` owns a cancellable lookup handle and a separate shared snapshot. The task retains only snapshot state, avoiding a handle/owner cycle. Request and channel resolver callbacks share native-only, serde-skipped state. Target/mode/server changes advance a generation and abort the previous task; old generations cannot publish into the current snapshot. Numeric/static/socket/proxied paths clear prior origin state. TXT lookup starts alongside address lookup, refreshes on eligible address resolution, and is not awaited before dialing. The pinned rejected-TXT-promise slot is retained after transport failure until the target changes.

The parser handles the first matching TXT record, fragment decoding, validation before canary predicates, language/hostname/percentage selection and normalized duplicate method names. RPC and reflection read the result before opening a wire stream. An accepted selector, including an initial default, survives a later invalid config. Exact/service/default method selection and method deadlines have application consumers. grpc_call_setup.rs selects retry/deadline policy before transport readiness; RPC and reflection invoke retry::streaming_prepared, which dispatches configured hedging when selected. grpc_retry_throttle.rs owns target token buckets. grpc_lb_transport.rs and the pick-first/round-robin modules implement routing; weighted/ORCA producers and outlier counters/ejection are connected to the pool. Do not restart these implementations from the older prerequisite checkpoints below.

Method deadlines preserve the pinned string component conversion, local Date setter ordering, millisecond truncation and earliest-deadline selection. Chrono 0.4.45 (already in the lock graph, now a pinned direct clock dependency) supplies OS local time; repeated local times select the earlier instant and skipped times use the preceding offset. Invalid/clipped Date results leave the previous deadline. Unrepresentable Chrono/OS local calendar ranges currently return an explicit error; complete ECMA Date extreme-range compatibility and timezone-data equivalence remain open. Local timer and wire deadlines are distinct: the pinned signed-32-bit timer cutoff and 8-digit wire-unit cutoff are retained, avoiding Tonic's out-of-range timeout panic. RPC work includes renderer delivery and response consumption under that budget. Each reflection driver retains its budget across descriptor batches/drain instead of restarting it; the outer discovery budget remains unchanged.

## Required resolver lifecycle

Address and TXT lookups start independently. Address success can deliver an initial configuration before TXT finishes; a later TXT result updates the same address list. TXT transport failure preserves the previous TXT result; malformed configuration is a different outcome. The resolver retains its last successful config while starting another address lookup. A failed address lookup is not converted into a successful resolution by a TXT reply. Numeric targets do not query TXT. The alternative-resolver flag controls which resolver receives DNS queries, including TXT; custom DNS authority alone does not enable alternative A/AAAA resolution. These rules come from [resolver-dns.ts](https://github.com/grpc/grpc-node/blob/%40grpc/grpc-js%401.14.4/packages/grpc-js/src/resolver-dns.ts).

Consequently, awaiting TXT before dialing or awaiting it unconditionally before every RPC would change the reference behavior. Lookup ownership must survive a successful channel connection, refresh with resolution, and terminate with its owning channel/cancellation scope. A detached task with no owned cancellation path is insufficient.

## Configuration selection and validation

The first TXT record whose first fragment has the configuration prefix supplies the JSON document; fragments of that record concatenate. Candidates validate before their selection predicates are checked. Selection uses the legacy language identity `node`, exact OS hostname, and one random percentage retained per resolver. Exhausting all candidates throws, despite the extraction function's comment suggesting a null result. An absent configuration record returns null.

Keep the validator's field types, empty-name normalization, duplicate method-name rejection, mutually exclusive retry/hedging policies, status-code validation, duration forms, and canary unknown-field rejection. Method lookup chooses exact service/method, then service, then empty default; it selects one config rather than merging them. ## Transport integration still required

Current `grpc_transport::channel` returns a bare Tonic `Channel`. Calls and reflection separately create Grpc clients, and the outer IPC deadline starts before connection. The implementation needs an owned resolution-policy carrier shared by these paths; an already-running call must not receive a fresh full budget when configuration arrives.

Retry/hedging is an attempt lifecycle, not a loop around `client.streaming`. Preserve message buffering, commitment, previous-attempt metadata, backoff/jitter, server pushback, cancellation, throttling and deadline ownership. [retrying-call.ts](https://github.com/grpc/grpc-node/blob/%40grpc/grpc-js%401.14.4/packages/grpc-js/src/retrying-call.ts) and [internal-channel.ts](https://github.com/grpc/grpc-node/blob/%40grpc/grpc-js%401.14.4/packages/grpc-js/src/internal-channel.ts) establish these boundaries. In particular, replay after an attempt is committed is not permitted. Reflection must use the same policy selection and cancellation model.

The implementation sequence is resolution-state ownership and parser/selector, asynchronous DNS delivery and refresh, call/reflection policy application, then load-balancing and retry/hedging/throttling. None of these steps substitutes for the remaining steps or closes overall parity. Do not enable a TXT-only parser while silently treating policy application as complete.
